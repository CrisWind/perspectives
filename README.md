# Perspectives

多视角决策 Agent：你说出正在纠结的事和自己的理由，几个思维方式和你不同的角色逐条检验你的理由，最后给你一张决策卡和带条件的建议。

虹桥国际科技周黑客松，AI Agent 赛道。

- 接口说明（前端看这个）：[docs/api.md](docs/api.md)
- 后端：[backend/](backend/)

## 启动后端

需要 Python 3.11 以上和 [uv](https://docs.astral.sh/uv/)。

```bash
cd backend
uv sync
cp .env.example .env    # 填模型密钥；不填也能跑，用的是模拟模型
uv run uvicorn app.main:create_app --factory --port 8000
```

打开 http://localhost:8000/docs 可以直接试接口。

**密钥只写在 `backend/.env` 里。这个仓库是公开的，`.env` 已被 git 忽略，不要把密钥写进任何会提交的文件。**

没有配置密钥时后端使用内置的模拟模型：流程、事件和数据结构与真实模型一致，发言内容是模板拼出来的。前端联调和跑测试用它就够了。

## 模型配置

各家模型都走 OpenAI 兼容接口。在 `.env` 里填了哪家的 `*_API_KEY` 就启用哪家，内置了 DeepSeek、通义千问、智谱、Moonshot、豆包、OpenAI 的地址，其他服务用 `LLM_EXTRA_PROVIDERS` 添加。

- 多家同时启用时，角色轮流分配到不同的模型上，质量检查和决策卡用 `JUDGE_PROVIDER` 指定的那家。
- 一家调用失败会自动换下一家。
- `.env.example` 里的默认模型名可能已经过时，请以各家控制台为准。

联网查证是可选的：配置 `SEARCH_PROVIDER`（`tavily` 或 `bocha`）和 `SEARCH_API_KEY` 后，查证角色会先搜索再发言；不配置时，查证角色不会引用任何来源。

### 一场辩论怎么进行

1. 澄清：把用户的话拆成理由清单，缺关键事实时追问（最多两个问题）。
2. 组队：按用户的 MBTI 选思维互补的三个角色，保证其中有查证角色，再加上"未来的你"。
3. 第一轮：各角色同时独立作答，互相看不到。两个角色独立想到同一点时，记为"不谋而合"，不算重复。
4. 交叉质询：角色轮流发言，能看到论点池，系统每次指定一条被检验得最少的理由作为重点。
5. 挑战底线：针对用户倾向的挑战少于 `MIN_CHALLENGES` 条时，加一轮点名补充。
6. 决策卡：理由体检、漏掉的视角、核心取舍、带条件的建议。

### 质量引擎

每条发言显示之前要过这些检查，不过就打回重写（默认最多重写两次）：

- 论点去重：先比字面相似度，再由裁判模型判断语义是否重复。
- 立场账本：改变立场必须指明被哪条别人的论点说服，否则不承认这次改变。
- 人设检查：裁判模型判断发言是否符合角色的风格和思维框架。
- 来源核对：论点引用的链接必须真实出现在搜索结果里，否则去掉。
- 决策卡核对：引用的论点编号必须存在，每条理由都要有结论，建议至少两条且带条件。

重写次数用完后降级处理：重复的论点丢弃，说不出理由的立场变化撤销，并在发言上做标记。

创建会话时传 `options.quality_engine: false` 可以整体关掉质量引擎，这就是评测里的对照组 C。

### 自进化

| 层 | 学什么 | 什么时候发生 |
|---|---|---|
| 个人 | 用户的 MBTI、过去的决定、看重的东西 | 每场辩论结束、每次反馈 |
| 群体 | 经验库：哪种追问方式在哪类决策里被认为有价值 | 用户把论点标为"没想到"或"有用"时立即发生 |
| 系统 | 角色提示词的补充准则 | 手动触发：起草，过门槛评测后上线，可回滚 |

防讨好的规则是写死的：

- 只收集"这条论点有没有价值"，不收集用户是否同意结论、是否改变主意。
- 支持用户倾向的论点即使被标为有价值，也不进经验库。
- 新的补充准则如果让该角色的挑战变少，过不了门槛。
- 每场辩论有挑战数量的底线。

系统层的门槛评测是在几道预设题上各跑一遍新旧版本做比较，样本很小，结果有随机性，上线前建议人工看一眼候选准则的内容。

## 评测

```bash
cd backend
uv run python scripts/run_eval.py     # 预设难题，四种方案
uv run python scripts/run_eval.py --questions my.yaml   # 自己的题库，格式同 app/content/presets.yaml
```

四种方案：A 单个 AI，B 一个模型扮演多个角色，C 多智能体但关掉质量引擎，以及完整系统。所有方案的输出用同一个抽取器抽论点、同一个聚类器统计不重复论点、同一个裁判判人设，完整系统不使用自己上报的数字。

结果在 `backend/eval_out/`：`summary.md` 是对比表，`results.json` 是明细，`blind/` 是打乱顺序的盲评材料（答案在 `_key.json`）。

## 游园会之前

```bash
cd backend
uv run python scripts/warm_presets.py
```

把每道预设题和每种队伍组合提前跑好存起来，现场的快速模式直接回放，不依赖模型当场响应。按目前的内容是 6 道题乘 17 种队伍，共 102 场，用真实模型跑要花一些时间和额度，请提前跑。修改了角色、预设题、模型配置或上线了新的补充准则之后，缓存会失效，需要重新跑。

快速模式回放的是缓存，所以当天新学到的经验不会出现在回放里；深度模式是现场生成的，会用上。
