# Perspectives 项目说明（2026-11-16 版）

标了"待定"的地方是建议，还没经过全组确认。

## 一、一句话介绍

Perspectives 是给大学生做选择用的调研型决策助手：你说出正在纠结的事和自己的理由，它先查事实，再让几个思维方式和你不同的角色逐条检验你的理由，最后给你一张决策卡、带条件的建议，和一份“做决定前还要验证的事”的清单。

**两条赛道**（2026-11-16 确定）：

| | 职业选择（主） | 生活烦恼（辅） |
|---|---|---|
| 典型问题 | 产品岗还是运营岗；大厂边缘业务还是小公司核心岗；考研还是工作 | 宿舍矛盾要不要摊牌；要不要转专业；留在大城市还是回老家 |
| 难在哪 | 缺事实：岗位差别、行业内幕、成长性、信息时效 | 缺自我澄清：自己到底看重什么 |
| 产品重点 | 联网检索、资料带日期和来源、岗位对照卡、待验证清单 | 价值观梳理、反讨好、安全边界 |

**不是什么**：不替用户拍板，不投票，不做岗位推荐榜单和薪资预测，不是心理咨询，不做心理诊断。

口号（待定）："让和你不一样的人，帮你想清楚"。

## 二、解决什么问题

人纠结的时候会找人商量，但商量对象都有毛病：

- 身边的人视角单一或自带立场，父母求稳，朋友顺着你说。
- 单个 AI 倾向于附和用户，而且只有一个视角。
- 自己想容易绕圈子、内耗，想不到自己没想到的事。

目标用户是大三、大四和研一的学生，场景是做决定前的几天：选岗位、选 offer、考研还是工作，以及校园里的人际和去向问题。他们的共同处境是身边没有行业里的人可问，想事情容易绕圈子，问通用 AI 又容易被顺着说。

## 三、用户最后拿到什么

不替用户拍板，但也不是什么都不给。决策卡包含五样东西：

1. 理由体检：每条理由站不站得住。
2. 漏掉的视角：用户自己没想到的点。
3. 真正卡住你的取舍：比如说到底是稳定和成长之间的选择。
4. 带条件的建议："如果你更看重 X，倾向 A；如果 Y 成立，B 更好"。
5. **待验证清单**：做决定前还没被证实、却会改变结论的事实，每条写清要核实什么、去问谁或去哪查、结果怎么影响决定。AI 替代不了行业里的人，但可以告诉你该去问他们什么。

决策卡还附资料来源列表，每条带发布日期。

## 四、使用流程

1. 说清楚：用户输入要做的决定、目前倾向和理由，Agent 把理由拆成清单，缺关键事实就追问。职业选择里还会请用户写专业、年级、做过的事、什么事做起来有劲、什么事耗人。
2. 查证：联网检索岗位和行业信息，结果带发布日期和来源；用户提到的岗位如果有团队核对过的岗位对照卡，一并带上。
3. 组队：按用户的 MBTI 挑选思维互补的角色。
4. 辩论：第一轮各角色独立作答，互相看不到；之后针对每条理由交叉质询。用户可以随时插话，或对某条结论提出不同意。
5. **主持 AI 把关**：每轮结束后，主持 AI 根据数字（新增论点数、被打回次数、还没检验的理由、立场是否稳定）决定继续、补查事实、向用户提问还是收尾，决定和理由会展示给用户。主持 AI 只管流程，不对用户的问题表态。
6. 决策卡：输出上面说的五样东西。
5. 反馈：用户标记哪些论点"没想到"、哪些"没用"。
6. 进化：系统从反馈里提炼经验，下一次用得上。

## 五、核心机制

1. **角色 = 人格 × 思维框架**。人格负责好玩（说话风格、MBTI 标签、头像），框架负责专业（事前验尸、逆向思考、10-10-10 法则、机会成本等）。
2. **质量引擎**，这是要做精的部分：
   - 论点池与去重：每条发言抽成结构化论点，只能提新论点、反驳或补证据，重复的打回重写。
   - 立场账本：角色改变立场必须说明被哪条论点说服。
   - 人设检查：发言偏离人设就重新生成。
3. **查证**：至少一个角色能联网查资料，用事实说话。
4. **事实纪律（职业选择）**：用户会拿角色的话做求职决定，所以岗位、行业、薪资这类事实只能来自团队核对过的岗位对照卡和带日期的联网资料，没有出处的写成“需要核实”；不预测薪资和前景，不给岗位排名；资料超过两年要提醒行情可能已变。决策卡里的资料来源由后端从真实搜索结果生成，不由模型编写。
5. **岗位对照卡**：先做计算机专业，6 到 8 个岗位，每张写日常工作、入门要求、常见发展、和易混淆岗位的区别，每条标来源，人工核对后才生效（和思想家语料同一规则）。不写薪资和行情，那些由联网检索实时提供。
6. **思想家嘉宾（暂缓，归入生活烦恼赛道）**：王阳明、苏轼这类历史思想家，发言附原文引用，系统核对引文逐字出现在原文里才显示。语料还没人核对，目前不会出场。不做领袖人物和当代政治人物，有被取消资格的风险。

## 六、自进化

进化的是三层东西，都不改模型本身：

- 个人层：记住这个用户的价值取向和过去的决定。
- 群体层：经验库，记录什么样的挑战在什么类型的决策里真正有用。
- 系统层：根据失败案例改进角色的提示词。

关键设计是防止越进化越讨好用户："用户同意结论"和"用户改变主意"都不算奖励，只有"用户认为这个挑战有价值"才算。每次辩论必须保留一定数量针对用户倾向的挑战。新版本要先通过评测门槛才上线，变差可以回滚。

## 七、两种模式

- 快速模式：选一张预设难题卡、选自己的 MBTI，一分钟看完，用于游园会拉票。回放的是预先生成的缓存，界面上要标明是示例回放。
- 深度模式：输入自己的难题，走完整流程，用于答辩和真实使用。**答辩必须用深度模式现场运行**，不能用缓存回放。

## 八、怎么证明比别人好

评委心里最大的疑问是"让豆包扮演五个人吵一架不就行了"，所以设三个对照组：

- A：把难题直接交给单个 AI。
- B：一段提示词让一个模型扮演多个角色。
- C：多智能体但不带质量引擎。

用 20 到 30 道真实难题测试（职业选择为主，要有用户明显有倾向的题），指标包括：不重复论点数、重复率、人设一致性、无理由改变立场的次数、抗讨好能力、真人盲评胜率，以及事实性指标“事实性论点中带来源的比例”。样本小，答辩时说"在 N 道题上的对比结果"，不说"显著优于"。

## 九、竞品和我们的差异

最接近的是国外的 Moot（五个 AI 人格辩论后投票），用户差评集中在论点浅、重复、角色说一套投一套。此外有一批开源同类项目（llm-council 衍生项目、16minds-plugin、AgentVerse）、黑客松作品（知乎"赛博辩论竞技场"等）和评理类应用（Mendus、情侣吵架AI判官）。

我们的差异：

1. 围绕用户自己的理由辩论，不辩抽象话题。
2. 给带条件的建议，不投票、不判输赢。
3. 用质量引擎保证辩论不是演出来的，并用数据证明。
4. 能从用户反馈里进化，游园会当天观众的反馈就是进化的素材。
